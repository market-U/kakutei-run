# Node.js セキュリティ更新の設計

## Context

開発シェルと nvm default は24.14.0、直近 CI は22.23.3を使用していた。公式の2026-10-21セキュリティ更新は22.23.4と24.22.1である。npm audit は Node 本体を検査しない。

## Goals / Non-Goals

開発・CI のアプリ用 Node.js を修正版に更新し、デプロイまで実行確認する。Azure の管理基盤全体や他プロジェクトの旧 Node インストールの削除は対象外とする。

## Decisions

- .nvmrc は22.23.4を指定し、setup-node v6 は node-version-file で同じ値を読む。package.json の engines は ^22.23.4 || ^24.22.1 とし、利用可能なメジャーごとに安全な下限を設定する。
- 開発機の24系と nvm default は24.22.1へ更新する。既存の22.23.4も用い、両方の環境でテスト・ビルドを実行する。
- checkout と setup-node は v6 に更新し、Node.js 24 のアクション用ランタイムを使う。アプリ用 Node の指定とは独立しているため、両方を記録する。
- Azure デプロイは現在の公式 Docker アクションを利用する。dist をアップロードし、Oryx によるアプリビルドはスキップする。本番アプリは静的ファイルとブラウザー上の JavaScript である。
- 既存 PR #94 の依存更新を取り込み、今回のコミットも同じ PR にまとめる。別々の engines 要件の衝突を防ぐ。

## Risks / Trade-offs

- 固定したパッチの陳腐化 → セキュリティ更新時に .nvmrc と engines の下限を更新する運用を README に明記する。
- アクション内部のパッチ番号はリポジトリから制御できない → 実行元 GitHub と Azure の管理範囲として記録し、安全性を断定しない。
- 開発シェルの PATH は既存プロセスに残る → nvm use または新しいシェルでの反映方法を案内する。

## Migration Plan

設定とロックファイルを更新し、修正版22系・24系で検証後に PR #94 を更新する。GitHub の CI ログから22.23.4とデプロイ成功を確認する。

## Open Questions

Azure デプロイ用コンテナ内部に含まれる全 Node.js のパッチ番号は未確認。アプリ用 Node.js の実行はスキップされる。
